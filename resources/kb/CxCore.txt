;; CxCore — Vaelii's vocabulary context: the engine-interpreted special
;; predicates (types, contexts, rules, metadata, evaluables) and the predicate
;; meta-ontology, each documented via a comment sentex. Schema only — the domain
;; relations, individuals, and facts live in other contexts.
;;
;; The test for belonging here is **grammar, not subject matter**: a term earns a place
;; only if it is vocabulary several upper-spindle members state their content *in*.
;; binary_predicate, arg, genl and unreifiable_function are grammar — every domain
;; declares its relations, constraints, types and functions with them. dimensionOf and
;; partOfRegion are not: they are *about* something (measurement, space), so they live
;; in the one upper context that owns that subject (kb/upper/CxMeasure.txt,
;; kb/upper/CxSpace.txt). A term whose only user is a single upper context belongs
;; in that context, whatever interprets it — being read by a prover does not make a term
;; part of the grammar.
;;
;; What that buys is separability, not omission: the starter loads every upper context
;; it finds, but a KB assembled from CxCore plus the layers it wants carries only
;; the subjects it reasons about, and nothing here has to change to add or drop one.

(comment abducible_predicate
         "(abducible_predicate ?predicate) means that a (?predicate …) sentence may be hypothesized. When a backward proof dead-ends on one, abduce may assume it rather than fail. A grant, and the only thing that makes a predicate abducible: an undeclared one is never assumed, since an abducer that will hypothesize anything explains everything and is worth nothing. Read from the asking context's genlCx ancestor set rather than universally, so it is a policy of the context that gives it — one theory may be willing to assume what another, reading the same vocabulary, will not.")
(unary_predicate abducible_predicate)
(genl abducible_predicate predicate)

(comment closed_extent_predicate
         "(closed_extent_predicate ?predicate) means that ?predicate's believed extent is complete: everything that holds of it is already derivable, so nothing answering (?predicate …) is what answers (not (?predicate …)). A grant, and the only thing that closes an extent — an undeclared predicate stays open-world, where an argument nobody has typed cannot violate a constraint and a fact nobody has stated is not thereby false. Read from the asking context's genlCx ancestor set rather than universally, so it is a policy of the theory that closes the extent: one may state the twelve months and read a thirteenth as refuted, while a sibling reading the same predicate answers only what it was told. Belief-following: a defeated or retracted member leaves the extent, and a closed (not (?predicate …)) rule antecedent is negation as failure, withdrawn when a member arrives.")
(unary_predicate closed_extent_predicate)
(genl closed_extent_predicate predicate)

;; singular twin and composes conjunctively with it — a position-specific arg and a
;; covering args both bind the slot, neither overrides.  A largest finite arg would make
;; an unbounded relation look finite; a covering constraint states the repeated role once.

Conjunctive with a position-specific (arg P n T). Open-world as arg is: an argument whose type is unknown cannot violate it. ;; The value kinds — the EDN kinds an argument written as a value can carry, placed in
;; the genl lattice so (quotedArg p n number) admits an integer and a bare type reaches
;; thing.  A
;; quoted argument is classified by kind (checks/value-kind), not by any stored
;; membership, so these need only their place in the hierarchy.
;;
;; These are the KB's ONLY names for the kinds a value can carry, and there is
;; deliberately no parallel domain vocabulary beside them.  The use/mention distinction is
;; carried by the DECLARATION — arg types what an argument denotes, quotedArg types the
;; term written there — and not by a second set of type names: a string value denotes
;; itself, so both questions are asked of one set, and (arg comment 2 string) and
;; (quotedArg p n string) name the same type for the same reason.  A second spelling buys
;; nothing and costs a trap, quotedArg reading a type outside this lattice open-world
;; (checks/syntactic-type?): a declaration naming the other spelling is silently inert.
;;
;; symbol is the exception, and is mention-only.  A symbol does not denote itself, so the
;; set of names and the set of things named are not one set — parentOf is written as a
;; symbol and denotes a predicate.  So symbol gets no domain placement and no
;; disjointness below; a use-level claim about it would be false of every predicate name.
;; One name per leaf kind a sentence can carry, and the set is complete on purpose.  A
;; value is typed by what it IS rather than by what somebody asserted, so a kind with no
;; name here is one the argument checks cannot place and must wave through — which is a
;; hole in a declaration rather than a policy.  A COMPOUND is the one exception and gets
;; no name here: what (QuantityFn 5 Meter) denotes is its function's business, so the
;; argument checks read it off result / genlResult instead and no kind would be the
;; right answer.

;; The four sign-refined integer collections are defined by DEFNS, not rules, so
;; membership resolves by EVALUATION at query time (integer / greaterThan / lessThan are
;; computed, never stored) at zero sentex cost: DefnSufficientProver admits a member whose
;; sufficient condition holds, DefnNecessaryNegationProver proves a non-member whose
;; necessary fails.  A defnSufficient and a defnNecessary carry the same condition, so each
;; collection is defined both ways.  No conjunct of the condition is stored, so the
;; defnSufficient expands to no forward rule.
(defnSufficient positive_integer (and (integer ?x) (greaterThan ?x 0)))
(defnNecessary  positive_integer (and (integer ?x) (greaterThan ?x 0)))
(defnSufficient negative_integer (and (integer ?x) (lessThan ?x 0)))
(defnNecessary  negative_integer (and (integer ?x) (lessThan ?x 0)))
(defnSufficient non_negative_integer (and (integer ?x) (greaterThan ?x -1)))
(defnNecessary  non_negative_integer (and (integer ?x) (greaterThan ?x -1)))

(defnNecessary  non_positive_integer (and (integer ?x) (lessThan ?x 1)))

;; The expression kinds — what a sentence is BUILT OUT OF, named as collections so a
;; declaration can type an argument by the FORM of the expression written there rather
;; than by what it denotes.  The value kinds above name a leaf; these name a compound.
;;
;; The ladder is the standard one, and the docs are held to it (docs/naming.md's reserved
;; words).  An ATOMIC_FORMULA is a predicate applied to terms.  An ATOMIC_SENTENCE is a
;; closed atomic_formula.  A LITERAL is an atomic_formula or its negation.  A FORMULA is
;; an atomic_formula, a logical operator applied to formulas, or a quantifier binding
;; variables in one.  A SENTENCE is a closed formula — which is what every stored sentex
;; holds, since checks/check-ground refuses an open non-rule sentence and a rule's
;; variables are implicitly universal.
;;
;; A RELATION_APPLICATION is the shape an atomic_formula and a non_atomic_term share: a
;; relation applied to arguments.  Which of the two it is depends on whether the relation
;; is a predicate or a function, and the two specializations below say so.  They are
;; disjoint, and the pair is not declared a covering of relation_application.
;;
;; DOCUMENTARY: nothing in the engine reads these.  An argument declaration over one
;; types no compound, because a compound argument has no knowable kind —
;; checks/value-kind answers nil for a compound by design (docs/argtypes.md), and no
;; reader classifies a compound by its shape.  So (quotedArg P n relation_application)
;; is inert, and the arg form convicts only a value written in the position and derives
;; a membership only for a symbol written there.  The declarations below that type a
;; sentence or a condition (believes, ist, implies, the defn family) read
;; the same way.  The vocabulary is here because it should be one vocabulary when a
;; shape classifier does exist; the classifier itself does not.
(comment relation_application "A relation applied to zero or more arguments — the shape (R a1 a2 ...) has, whatever R is. Specializes into atomic_formula when R is a predicate and non_atomic_term when R is a function, and the two are disjoint.")

(comment atomic_sentence "A closed atomic_formula — one with no free variables. What a stored LiteralSentex holds in its sentence slot.")
(comment literal "An atomic_formula or its negation. What a LiteralSentex holds, with the record's polarity slot saying which of the two it is. A rule's antecedent is a vector of literals.")
(comment formula "An atomic_formula; a logical operator applied to formulas; or a quantifier binding variables in a formula. Open when it has free variables, closed when it does not.")

;; declaration already descends the predicate hierarchy, so (fixed_arity_predicate Fred)
;; with Fred a person derives (relation Fred) from (arg fixed_arity 1 relation), a clash
;; with person.  And a NARROWER declaration below — (arg fixed_arity_predicate 1

;; variable_arity reaches relation and not predicate, so (binary_predicate P) after
;; (variable_arity P) would be derived a predicate where the contradiction is the arity
;; policy, which the disjointness below stores as a clash.  A relation classified into the wrong kind is
;; caught by (disjoint predicate function), which the partition of relation derives,
;; through the genl edges instead.

;; The meta-ontology rules below conclude into the ORDINARY placement — the maximal
;; context that sees the rule and the declaration — and not into a named one.  Every
;; context sees CxCore, so a declaration made here still concludes here; one made
;; in a context concludes there, where its author put it.  Naming CxCore would
;; publish it: a private (symmetric myRel) would become vocabulary the whole KB reads,
;; while (has-prop? kb :symmetric myRel ctx) — asked of the same declaration from the
;; same context — answered false.  One KB cannot say both.

;; relationTypeByArity is the one rule-bearing family.  Predicate and function mappings
;; are its genl specializations rather than parallel arity/type rules.  It is a generator
;; (docs/generators.md): one minted rule per mapping fact, its (?type ?relation)
;; consequent ground once the enclosing antecedent fills ?type, justified by that fact and
;; withdrawn with it.
;;
;; The rule runs one way: an exact arity classifies the relation under the type that
;; maps to it.  No rule concludes an arity, because arity is on the forced-monotonic
;; roster and a classification is not; every reader of an arity reads the exact-arity
;; class membership beside the (arity P n) table (docs/taxonomy.md).  RELATION-WIDE, and
;; it has to be — arity covers functions, so a rule concluding (binary_predicate ?r) from
;; (arity ?r 2) would make every shipped binary function a predicate and clash with
;; (disjoint predicate function); (binary ?r) carries no kind and is what the arity
;; actually says.  An arity no class maps to concludes nothing — (arity InstantFn 6)
;; leaves InstantFn fixed_arity_function by its own declaration.
(implies (relationTypeByArity ?type ?arity)
         (set/forwardRule (implies (arity ?relation ?arity) (?type ?relation))))

;; The three relation-wide classifications separate each other: a relation takes ONE
;; exact number of arguments, so a second classification is a contradiction rather than
;; a second fact.  This keeps the (arity ?relation ?n) table single-valued at its source:
;; two exact classes would derive two arities, and (functional arity) would otherwise
;; convict a clash the class declarations had already made.
;;
;; The predicate and function specializations inherit that separation through their genl
;; edges to the relation-wide classes (unary_predicate genl unary, and so on): restating
;; the three predicate pairs here would only duplicate it.  Nothing marks predicate as
;; (sibling_disjoint predicate) — its specializations include many compatible
;; classifications, and only the exact-arity classes exclude one another.
(set/monotonic (disjoint unary binary))
(set/monotonic (disjoint unary ternary))
(set/monotonic (disjoint binary ternary))

;; ---- definitional collection relations -----------------------------------
;; Three relations tie a collection's membership to a defining condition on the member
;; ?x, each expanded into ordinary forward rules at assert (docs/defns.md).  The fact is
;; stored like any other — so it retracts and belief-follows — and its condition argument
;; is a sentence carrying ?x, which is why arg 2 is typed as a thing (a compound term is
;; typed by what its function is declared to yield, and nothing declared fails to reach
;; thing) and arg 1 with genlArg (the collection names a kind, like disjoint's).
;; Neither relation_kind: they relate a kind to a sentence, so they are mixed and
;; left unmarked, as result is.

(comment defnNecessary
         "(defnNecessary ?collection ?condition) means that every instance of ?collection satisfies ?condition — a necessary condition on membership, written over the member ?x. Expands to the forward rule (implies (?collection ?x) ?condition), so an instance's membership entails the condition of it. Open-world: it says what members must satisfy, never that satisfying it makes a member (that is defnSufficient), and never that a non-member fails it.")
(binary_predicate defnNecessary)
(genlArg defnNecessary 1 thing)
(arg defnNecessary 2 formula)

(comment defnSufficient
         "(defnSufficient ?collection ?condition) means that anything satisfying ?condition is an instance of ?collection — a sufficient condition for membership, written over the member ?x. Expands to the forward rule (implies ?condition (?collection ?x)), so a thing meeting the condition is concluded a member. Open-world: it says what makes a member, never that a member must satisfy it (that is defnNecessary), and it draws no non-membership from the condition failing.")
(binary_predicate defnSufficient)
(genlArg defnSufficient 1 thing)
(arg defnSufficient 2 formula)

(comment defnIff
         "(defnIff ?collection ?condition) means that ?condition is both necessary and sufficient for membership in ?collection — an instance satisfies it exactly when it is a member, written over the member ?x. Expands to both forward rules defnNecessary and defnSufficient state, and nothing more: it does not close the collection's complement, so a thing whose condition is merely unknown is neither concluded a member nor concluded a non-member (docs/defns.md).")
(binary_predicate defnIff)
(genlArg defnIff 1 thing)
(arg defnIff 2 formula)

(comment intersection

Variable-arity; (intersection causal_event causal event) names a two-way intersection and further ?types extend it. arityMin is three: the combined kind plus at least two types, since the intersection of a single type is that type and drives no rule.")

;; --- defining rules (binary and ternary; general arity pends memberOfList, see the
;;     upstream list proposal). A combined kind is genl each type it intersects, and
;;     anything that is each type is a member of the combined kind. ------------------
;; Forward rules: an intersection fact materializes the genl edges when it is asserted,
;; so the derived edge reaches the taxonomy closure and answers a variable-free genl
;; goal at every read entry point. A bare (implies …) defaults to :backward, which the
;; closure-backed ask/ask? path expands no rule for and so never sees.
(set/forwardRule (implies (intersection ?combined ?type1 ?type2) (genl ?combined ?type1)))
(set/forwardRule (implies (intersection ?combined ?type1 ?type2) (genl ?combined ?type2)))
(set/forwardRule (implies (intersection ?combined ?type1 ?type2 ?type3) (genl ?combined ?type1)))
(set/forwardRule (implies (intersection ?combined ?type1 ?type2 ?type3) (genl ?combined ?type2)))
(set/forwardRule (implies (intersection ?combined ?type1 ?type2 ?type3) (genl ?combined ?type3)))
;; membership: the consequent's predicate is a variable, so a generator stamps a
;; concrete-functor rule per intersection fact.
(implies (intersection ?combined ?type1 ?type2)
         (set/defaultRule (implies (and (?type1 ?x) (?type2 ?x)) (?combined ?x))))
(implies (intersection ?combined ?type1 ?type2 ?type3)
         (set/defaultRule (implies (and (?type1 ?x) (?type2 ?x) (?type3 ?x)) (?combined ?x))))

;; ---- the predAll / predExists / predInstance / predSpecified matrix -------
;; A family of ternary relations that quantify one binary ?pred's two argument positions
;; against a collection or an individual, and fix the other.  Each name reads its two
;; positions in order — predAllInstance quantifies position 1 (All) and fixes position 2
;; (Instance); predInstanceAll fixes 1 and quantifies 2 — so the four *Instance* / *All*
;; combinations, the four *Exists* ones, and the *Specified* audit are one matrix.
;;
;; Unlike the defn* relations, these are NOT expanded into a single rule at assert: they
;; are **rule generators** (docs/generators.md — a rule whose consequent is a rule).  The
;; generator's antecedent grounds the predicate and the collection, and its firing stamps
;; a concrete rule with those holes filled, so one generator ranges over a whole family of
;; predicates while every rule the index keys carries a concrete functor.

;; --- Instance class: rule generators, real inference ----------------------
;; The quantified position ranges over a collection's members; the fixed position is a
;; given filler.  Stamping (implies (?coll ?x) (?pred …)) is ordinary forward inference,
;; so a member of the collection is concluded to bear ?pred to the fixed filler.

(comment predAllInstance
         "(predAllInstance ?pred ?indep ?fixed) means that every instance of collection ?indep bears ?pred to the fixed filler ?fixed at ?pred's first position: for all x in ?indep, (?pred x ?fixed). A rule generator (docs/generators.md), not a defn: it stamps the rule (implies (?indep ?x) (?pred ?x ?fixed)) — a defaultRule, bidirectional — with ?pred/?indep/?fixed ground, so a member arriving later fires it and the conclusion retracts and belief-follows like any derived fact. Forward, the stamped rule fires when membership is believed; backward, its antecedent is discharged inside a query/prove proof — including a bare literal's membership via the evaluative defnSufficient prover, so (predAllInstance sign negative_integer \"negative\") proves (sign -212 \"negative\") from the bare literal under query. Under ask the goal answers false by contract: the registry expands no rule (docs/levels.md).")
(ternary_predicate predAllInstance)
(arg predAllInstance 1 binary_predicate)
(genlArg predAllInstance 2 thing)
(implies (predAllInstance ?pred ?indep ?fixed)
         (set/defaultRule (set/forwardRule (implies (?indep ?x) (?pred ?x ?fixed)))))

(comment predInstanceAll
         "(predInstanceAll ?pred ?fixed ?dep) means that the fixed filler ?fixed bears ?pred to every instance of collection ?dep at ?pred's second position: for all y in ?dep, (?pred ?fixed y). The argument-swapped twin of predAllInstance. A rule generator that stamps the bidirectional defaultRule (implies (?dep ?y) (?pred ?fixed ?y)) with the holes ground, so the descent to members is ordinary chain inference (docs/generators.md).")
(ternary_predicate predInstanceAll)
(arg predInstanceAll 1 binary_predicate)
(genlArg predInstanceAll 3 thing)
(implies (predInstanceAll ?pred ?fixed ?dep)
         (set/defaultRule (set/forwardRule (implies (?dep ?y) (?pred ?fixed ?y)))))

;; --- Exists class: pure record, inferentially inert -----------------------
;; Everything with "exist" in the name is INERT (Pace's ruling): the declaration is
;; stored and queryable like any fact, and the engine draws no inference from it — no
;; stamped rule, no skolemized witness, no defn ("skolems suck"), no materialized facts.
;; What each cell contributes beyond the record is a sanctioned PLACEHOLDER functor an
;; author MAY use to name the required-but-unnamed filler: a PER-CELL functor carrying
;; that cell's FULL argument list — "kinda like a named skolem" (Pace) — deliberately
;; DISTINCT per cell, because the markers are ontology now and eventually it will matter
;; that they are different.  Asserting a placeholder into a sentence (its collection
;; membership, its relation to a subject) is the author's act, not the engine's; when
;; asserted, the placeholder is determinate — it satisfies a predAllSpecified audit —
;; where a skolem witness would not be.  Each functor is unreifiable_function so its
;; ground application stays a structural NAT, readable inside the sentence.
;;
;; Inertness is also what makes all FOUR cells expressible.  An earlier design stamped a
;; rule per declaration via a generator; the two pure-existential cross-cells
;; (predExistsInstance / predInstanceExists) have no universal to range over, so the
;; generator form failed range restriction there, and the plain-rule form — a
;; variable-functor consequent — filed in the concluding-rule catch-all and made the
;; planner see a phantom rule for EVERY predicate (broke aggregate / STP / QCN /
;; interval / distance reasoning KB-wide, verified).  An inert record stamps nothing,
;; so there is nothing to fail and nothing to pollute: the asymmetry between the
;; straight cells and the cross-cells dissolves with the inference.

An unreifiable_function, so a ground application stays a structural NAT the reader keeps readable inside the sentence; per-cell and full-arg (\"kinda like a named skolem\"), distinct from the other Exists cells' placeholders. An ontological marker, deliberately NOT a skolem witness: the engine never asserts it anywhere — its uses are the author's — and when used it is determinate, so it satisfies a predAllSpecified audit. (comment injection
         "(injection ?predicate) means that ?predicate is an injective function: single-valued, one-to-one, and total on the type its first argument is declared to be. Declared once, it stands in for four claims the engine already reads. Two forward rules derive (functional ?predicate) and (functionalInArg ?predicate 1), each a real mark the engine enforces in turn: the merge-or-nogood rule over a shared first argument, and the same rule mirrored over a shared second. A second symbol filler on either side, both facts monotonic, derives (equals V1 V2) and merges, while any other collision, such as 1980 and 1990, is a nogood. A third rule reads the domain off (arg ?predicate 1 ?d) and derives the binary integrity requirement (predAllSpecified ?predicate ?d); the required filler type is not restated — the audit derives it from ?predicate's own slot-2 contract at read time. Totality is audited rather than enforced because an open world cannot refuse a write for a member whose filler has not arrived. A predicate with no arg 1 declaration gets the two enforced marks and no audit, since nothing states what the domain is; one typed at arg 1 but not at arg 2 concludes the requirement, and the audit reports the missing slot contract as an explicit gap rather than auditing unconstrained. A one-to-one relation that is not total is (functional P) beside (functionalInArg P 1), written directly. Also a type: (genl injection functional) classifies P as functional and so binary_predicate. Declared of a relation such as capitalCityOf, for instance. See docs/taxonomy.md.")
(unary_predicate injection)
(decontextualized_predicate injection)
(genl injection functional)

(comment surjection
         "(surjection ?predicate) means that ?predicate is a surjective function: single-valued, total on the type its first argument is declared to be, and onto the type its second is. Declared once, it stands in for three claims. One forward rule derives (functional ?predicate), the mark the engine enforces by merging two monotonic symbol fillers for one first argument and deciding any other two as a nogood. Two further rules read the domain off (arg ?predicate 1 ?d) and the range off (arg ?predicate 2 ?r), and derive (predAllSpecified ?predicate ?d) for totality and (predSpecifiedAll ?predicate ?r) for ontoness — each binary, the filler's type derived from the predicate's own slot contract at read time rather than restated. Both are audited on demand by vaelii.core/specified-violations: the first reports the domain members with no determinate filler, the second the range members no determinate domain member reaches. Neither is enforced at a write, an open world having no ground to refuse a fact for a member nothing has reached yet. A predicate whose quantified side is untyped concludes no requirement; an untyped filler side is reported by the audit as an explicit gap. Nothing here says one-to-one, so a surjection may send two domain members to one range member; that is what separates it from bijection. Declared of a relation such as capitalCityOf over capital_city, for instance. See docs/taxonomy.md.")
(unary_predicate surjection)
(decontextualized_predicate surjection)
(genl surjection functional)

(comment bijection
         "(bijection ?predicate) means that ?predicate is a bijective function: an injection and a surjection at once, so the two declared types are in one-to-one correspondence. Declared once, it stands in for the pair: two forward rules derive (injection ?predicate) and (surjection ?predicate), and each of those derives its own marks in turn, so the whole family reaches the engine through the two entries above rather than through anything keyed on this name. What lands is (functional ?predicate) and (functionalInArg ?predicate 1), enforced at the assert entry point, beside (predAllSpecified ?predicate ?d) over the arg-declared domain and (predSpecifiedAll ?predicate ?r) over the arg-declared range — binary, the filler types derived from the predicate's own slot contract at read time — audited on demand. The marks are materialized as stored sentexes rather than claimed by subsumption edges, for the reason equivalence_relation's entry gives: the rule's stored conclusion both classifies and enforces, where a genl-inherited membership never reaches the mark ingestion. Also a type: (genl bijection injection) and (genl bijection surjection) state the subsumption outright, and classify P as functional and so binary_predicate. Declared of a relation such as capitalCityOf over capital_city, for instance. See docs/taxonomy.md.")
(unary_predicate bijection)
(decontextualized_predicate bijection)
(genl bijection injection)
(genl bijection surjection)

;; The enforced half. Each derived mark is a real property the engine enforces exactly as
;; a directly written one is, so nothing is keyed on the three names above.
(set/forwardRule (implies (and (injection ?p))  (functional ?p)))
(set/forwardRule (implies (and (injection ?p))  (functionalInArg ?p 1)))
(set/forwardRule (implies (and (surjection ?p)) (functional ?p)))
(set/forwardRule (implies (and (bijection ?p))  (injection ?p)))
(set/forwardRule (implies (and (bijection ?p))  (surjection ?p)))

;; The audited half. Totality quantifies over the domain and ontoness over the range, so
;; each rule reads only the ONE arg declaration that names its quantified collection —
;; the filler's own type is no longer restated anywhere, because the binary audit derives
;; it from the predicate's slot contract at read time. A predicate whose quantified side
;; is untyped concludes no requirement; one whose FILLER side is untyped concludes the
;; requirement and the audit reports the missing slot contract as an explicit gap.
(set/forwardRule (implies (and (injection ?p)  (arg ?p 1 ?d)) (predAllSpecified ?p ?d)))
(set/forwardRule (implies (and (surjection ?p) (arg ?p 1 ?d)) (predAllSpecified ?p ?d)))
(set/forwardRule (implies (and (surjection ?p) (arg ?p 2 ?r)) (predSpecifiedAll ?p ?r)))

(comment functionCorrespondingPredicate
         "(functionCorrespondingPredicate ?function ?predicate ?position) means that ?function and ?predicate state the same relationship: ?function maps some arguments to a value exactly when ?predicate holds of those same arguments with the value at ?position. So (functionCorrespondingPredicate MotherFn motherOf 2) makes (MotherFn Muffet) resolve to the Mary of a believed (motherOf Muffet Mary), and, where no mother is known, projects the placeholder constant it mints back onto motherOf so the placeholder still answers questions about who Muffet's mother is. (comment genl
         "(genl ?subtype ?supertype) means that every ?subtype is a ?supertype. Transitive, and cached as a closure rather than run as a rule, since transitivity is the lifeblood of common sense and far too hot to chain. The type hierarchy it builds is rooted at thing. Types are unary predicates, so membership is written (dog Muffet) and never (isa Muffet Dog). The same relation relates predicate specializations of any arity: every tuple of the subtype is a tuple of the supertype, which is what a type reading of it is the unary case of, so neither argument is declared a subtype of thing.")

;; NEITHER position is declared, and both are left so deliberately.
;; (genlArg genl 1 thing) reads "the subtype is a subtype of thing", which is false of
;; the predicate specializations genl also relates: (genl predicateTypeByArity

;; under the root. Under the assertive reading the declaration entails (genl
;; predicateTypeByArity thing) from that edge, which the arity descension check refuses
;; because a binary predicate's tuples are not a unary type's.
;; (genlArg genl 2 thing) reads "the supertype is a subtype of thing", which the root
;; cannot satisfy: genl is irreflexive here, so (genl thing thing) is refused as

;; A constraint the predicate's own arguments fail is the wrong constraint, not a missing

;; The two bridges between the three spellings, and the one to symmetric.
;;
;; commutative and (commutativeInArgAndRest P 1) are the same licence, and the engine has
;; no iff. Each mark installs the commuting group [:rest 1] at its own arm in
;; special/arms, so the canonicalizer reads one table whichever spelling was written and
;; neither spelling has to be derived from the other. The two directions stay here as
;; set/inertRule: believed, indexed and queryable, run by neither engine.
;;
;; They are inert rather than forward rules because a derivation between them is a cycle —
;; each conclusion justifies the other — and set/forwardRule adds forward chaining without
;; taking the backward use away. Forward chaining survives a cycle: the pair is unfounded
;; and the JTMS labels it so (docs/nmtms.md). Backward search does not.
;; provers/candidate-rules carries no ancestor-goal guard, so (commutative ?p) expands to
;; (commutativeInArgAndRest ?p 1) and back with no binding arriving to close it off. The
;; depth bound stops the descent, which makes the cycle an exponential frontier inside
;; that depth rather than a refusal, and (genl commutative relation) puts the goal under
;; every open (relation ?x) query — which is what made vaelii.arity-vocabulary-test never
;; finish under VAELII_QUERY_ENGINE=inference.
(set/inertRule (implies (and (commutative ?p)) (commutativeInArgAndRest ?p 1)))
(set/inertRule (implies (and (commutativeInArgAndRest ?p 1)) (commutative ?p)))

;; Every symmetric relation is commutative over its two arguments, stated as a genl edge.
;; The membership it gives is inherited rather than stored. The two rules above are inert,
;; so a symmetric P carries no second group: symmetric sorts its own two arguments, and
;; the canonical form is the one it already produced.
(genl symmetric commutative)

;; The converse needs the arity, and is a rule because it concludes a mark the engine
;; enforces: commutativity at two arguments IS symmetry, where commutativity at any other
;; arity implies neither symmetry nor arity 2.  It reads the (arity ?p 2) declaration and
;; not the (binary ?p) class: every symmetric predicate is binary and commutative through
;; its genl edges, so a class antecedent would re-derive each symmetric mark from itself.
;;
;; forwardOnlyRule, not forwardRule: set/forwardRule adds forward chaining without taking
;; the backward use away, and backward this rule is a cycle. The genl edge above makes
;; symmetric a spec of commutative, so provers/candidate-rules offers a rule concluding
;; (symmetric ?p) as a candidate for the goal (commutative ?p) — which is the very goal
;; this rule's own antecedent poses. Nothing stops the descent: candidate-rules carries
;; no ancestor-goal guard, and the depth bound turns the cycle into an exponential
;; frontier rather than a refusal. (genl commutative relation) puts that goal under every
;; open (relation ?x) query, so the cycle reached every caller of the inference engine.
;; Forward chaining has no such trouble — it derives (symmetric P) once and reaches a
;; fixpoint — so the rule keeps the direction that does its work and drops the one that
;; does not.
(set/forwardOnlyRule (implies (and (commutative ?p) (arity ?p 2)) (symmetric ?p)))

;; metatype second-order (its instances are types), a meta_metatype third-order.
;; fixed_order_type is those three; variable_order_type holds members of any order;
;; at_least_metatype is metatype and up.  type_type_by_order partitions fixed_order_type
;; into the three orders.
(comment type "A first-order type — its instances are individuals, not types. Contrasts with metatype (second order) and meta_metatype (third order).")
(comment metatype "A second-order type — its instances are types.")
(comment meta_metatype "A third-order type — its instances are metatypes.")
(comment at_least_metatype "A type whose instances are themselves types (at least second-order): metatypes, meta_metatypes, and any higher order.")
(comment fixed_order_type "A type all of whose members are of one order — a type, a metatype, or a meta_metatype. Contrast variable_order_type.")
(comment variable_order_type "A type that can hold members of any order.")
(comment type_type_by_order "A disjoint_metatype partitioning fixed_order_type into type, metatype, and meta_metatype.")
(comment partitionedByType "(partitionedByType ?whole ?classifier . ?cells) declares that the ?cells exhaustively and disjointly partition ?whole, and that each cell is an instance of ?classifier. Inert — the disjointness and the memberships are stated directly beside it.")
(variable_arity_predicate partitionedByType)
(arityMin partitionedByType 3)
(unary_predicate type)
(at_least_metatype disjoint_metatype)
;; Stated rather than left to (arg typeGenl 1 at_least_metatype) to mint, so the typeGenl
;; facts below satisfy their declaration under the constraint-only reading as well.
(at_least_metatype metatype)
(at_least_metatype meta_metatype)
(set/monotonic (disjoint_metatype type_type_by_order))
(genl at_least_metatype unary_predicate)
(genl disjoint_metatype at_least_metatype)
(genl meta_metatype at_least_metatype)
(genl metatype at_least_metatype)
;; A unary predicate holds members of one order or of any order: the partition separates
;; fixed_order_type from variable_order_type and installs each genl edge to unary_predicate.
(set/monotonic (partition unary_predicate fixed_order_type variable_order_type))
(interArg typeGenl 1 meta_metatype 2 metatype)
(interArg typeGenl 1 metatype 2 type)
(partitionedByType fixed_order_type type_type_by_order type metatype meta_metatype)
;; The partition's memberships and subtype edges, stated explicitly so the disjoint_metatype
;; separates the three orders and each is a fixed_order_type — partitionedByType is inert and
;; expands to nothing.
(type_type_by_order type)
(type_type_by_order metatype)
(type_type_by_order meta_metatype)
(genl type fixed_order_type)
(genl metatype fixed_order_type)
(genl meta_metatype fixed_order_type)
(typeGenl disjoint_metatype at_least_metatype)
(typeGenl meta_metatype metatype)
(typeGenl metatype type)
(typeGenl relation_kind binary_predicate)
(typeGenl type_type_by_order fixed_order_type)
;; sibling_disjoint holds types of any kind, so its typeGenl names the root.
(typeGenl sibling_disjoint thing)
;; Every at_least_metatype names a type its instances specialize, and every unary_predicate names a genl.
(predAllSpecified typeGenl at_least_metatype)
(predAllSpecified genl unary_predicate)
(variable_order_type at_least_metatype)
(variable_order_type fixed_order_type)
(variable_order_type variable_order_type)

;; A thing has mass or it does not: tangible and intangible partition thing, which records
;; the separation and the coverage both.  Nothing separates intangible from spatial or
;; spatiotemporal, since a region has a location and no mass.
(set/monotonic (partition thing tangible intangible))
;; A thing either has a location in some space or is aspatial, and is either in time or
;; atemporal: each pair is a complement, and each is a partition, which records the
;; separation and the coverage both.  The quality checker's schematic clash reading
;; prunes the phantom pairs these separations create by antecedent arg-type
;; disjointness (vaelii#95, fix(quality)).
(set/monotonic (partition thing spatial aspatial))
(set/monotonic (partition thing temporal atemporal))
;; The three partitions cut thing along three axes — location in some space, location in
;; time, mass — so a part of one may overlap a part of another.  The seven pairs below each
;; overlap with neither side subsuming the other; not every cross-axis pair does, since
;; tangible is below spatiotemporal and aspatial below intangible.  Stated, each pair reads
;; :orthogonal without waiting for a shared instance.  A witness of the overlap per pair, and of neither side holding the other:
;; a rock is spatial and temporal; the line y=x is only spatial; a time is only temporal.
(set/monotonic (orthogonal spatial temporal))
;; a number is aspatial and atemporal (nowhere_never); a time is aspatial and temporal.
(set/monotonic (orthogonal aspatial atemporal))
;; the line y=x is spatial and atemporal, located in the Cartesian plane and in no time.
(set/monotonic (orthogonal spatial atemporal))
;; a time is aspatial and temporal: it is in time and located in no space.
(set/monotonic (orthogonal aspatial temporal))
;; a region of space is intangible and spatial.
(set/monotonic (orthogonal intangible spatial))
;; a time is intangible and temporal.
(set/monotonic (orthogonal intangible temporal))
;; a region of space is intangible and spatiotemporal, occupying space without mass.
(set/monotonic (orthogonal intangible spatiotemporal))
;; A temporal thing is present at every moment between its start and its end, or it has a
;; gap.  The partition installs both parts' edges to temporal.
(set/monotonic (partition temporal uninterrupted intermittent))
;; A tangible is uninterrupted by default.  The edge is a default because a tangible
;; can be intermittent, e.g. a watch taken apart and rebuilt.
(genl tangible uninterrupted)
;; A thing either can be a cause or cannot, and a cause is in time.  CxAbstract comments
;; causal and acausal; the partition and the edges sit here so that every spindle member
;; reads them.  The partitions separate atemporal from causal but install no genl edge
;; from atemporal to acausal, so that edge is stated.
(set/monotonic (partition thing causal acausal))
(genl causal temporal)
(genl atemporal acausal)
