;; CxTra — vocabulary that is generally useful but specific to one domain, outside the
;; starter contexts CxWell sees: software tools, their invocations and receipts, media
;; resources and network names, information content, its carriers, and the sentences an
;; agent claims about it, and perception relations. Sees the shared upper
;; ontology via CxUniverse. CxWell does not see it, so the everyday contexts below CxWell
;; read none of this vocabulary. A context opts in by placing itself under CxTra.

(genlCx CxTra CxUniverse)
(comment CxTra "The opt-in middle context for vocabulary that is generally useful but specific to one domain, such as computing and perception, and so is not in a starter context that CxWell sees. CxTra sees CxUniverse. CxWell does not see CxTra, so a context reads the vocabulary only by placing itself under CxTra.")

;; ==== computing ===========================================================
;; The computing relations state no rule.
;;
;; The sixteen computing kinds that the relations here are typed over
;; (computational_system, software_tool, tool_invocation, media_resource, ip_address and
;; the kinds below them) are stated here too, with their comments, genl edges and
;; disjointness. A context that does not see CxTra reads none of them.
;;
;; Among the computing relations, two positions declare `thing`. Position 1 of agentHasTool holds whatever can invoke a
;; tool, and the upper ontology ships no type for that: registered_agent names a
;; registered koinii participant (resources/kb/koinii/CxRegistry.txt). Position 3 of
;; toolArgType holds a type of any kind, so it declares (genlArg toolArgType 3 thing).

;; ---- the computing kinds: the types the relations below are typed over ----
;; A software_tool is software that performs one bounded operation per invocation. It
;; has no mass, so it is placed under computational_system, which is intangible.
(comment computational_system "Software that computes when it runs.")
(set/monotonic (time_invariant_relation computational_system))
(positiveExampleComment computational_system "a running Python interpreter")
(positiveExampleComment computational_system "a running database server process")
(positiveExampleComment computational_system "a running web service")
(negativeExampleComment computational_system "the hardware that runs a computational system, which is a separate thing")
(genl computational_system intangible)
;; A computational system is not something that happens, and is not a form the KB
;; represents.
(disjoint computational_system event)
(disjoint computational_system expression)

(comment software_tool "A computational system that performs one bounded operation each time an agent invokes it.")
(positiveExampleComment software_tool "a command-line program")
(positiveExampleComment software_tool "a Model Context Protocol tool")
(positiveExampleComment software_tool "a web API endpoint")
(genl software_tool computational_system)
(set/monotonic (time_invariant_relation software_tool))

(comment command_line_tool "A software tool invoked by a command line that a shell runs.")

;; ==== content and carriers =================================================
;; information, among the computing kinds above, is the content: what a document says,
;; apart from the paper or the disk that holds it.  carries relates a temporal carrier to
;; the information it holds in its medium: a paper copy and the molecules of a cell's DNA
;; are tangible carriers, and a bird's chirp is an event, an intangible carrier.  A
;; digital artifact can be a carrier and content at once: a web page is information, and
;; the web page carries the article it shows.

(comment conceptual_work "Information composed as one work, which stays the same work in each copy and each encoding of it. A copy of a work is a carrier of the work and is not the work.")
(positiveExampleComment conceptual_work "the novel Moby-Dick")
(positiveExampleComment conceptual_work "the information content of a newspaper article")
(negativeExampleComment conceptual_work "a physical copy of a newspaper article, which carries the work")
(negativeExampleComment conceptual_work "the information content of a cell's DNA, which is information that nobody composed")
(genl conceptual_work information)

(comment carries "(carries ?carrier ?info) means that the temporal ?carrier holds ?info in its medium: reading the medium in the right way gives ?info. A carrier and the information it holds are two things, so destroying a carrier destroys the carrier and not, by that alone, the information. Not functional in position 2: one carrier holds more than one piece of information, e.g. a tree's rings hold the tree's age and each year's rainfall.")
(binary_predicate carries)
(set/monotonic (instance_relation_predicate carries))
(arg carries 1 temporal)
(arg carries 2 information)

(comment subInformationOf "(subInformationOf ?part ?whole) means that the information ?part is a component of the information ?whole, e.g. a chapter in a book or a frame in a video. A spec of intangiblePartOf, since information has no mass. Declared transitive, so a part of a part is a part.")
(set/monotonic (instance_relation_predicate subInformationOf))
(arg subInformationOf 1 information)
(arg subInformationOf 2 information)
(set/monotonic (transitive subInformationOf))
(set/monotonic (reflexive subInformationOf))
(genl subInformationOf intangiblePartOf)

;; Position 1 names the presenting agent; the upper ontology ships no type for one
;; (core.txt's believes states the same of its believer position), so it declares thing.
;; Position 2 holds a sentex handle (sentexHandle H), which the engine mints with no
;; result type, so it declares thing too, as koinii's endorses does (CxSpeechActs).
(comment agentClaims "(agentClaims ?agent (sentexHandle H)) means that ?agent presents the sentex named by the handle in position 2 as true. A claim is not a belief: the KB believes the sentex only where a context the reader sees asserts it. Declared target_following_predicate, so retracting the sentex retracts each claim that names it. No rule concludes agentClaims from carries: a carrier that holds a sentex by quoting, denying or mocking it is not thereby concluded to present it as true.")
(binary_predicate agentClaims)
(set/monotonic (instance_relation_predicate agentClaims))
(arg agentClaims 1 thing)
(arg agentClaims 2 thing)
(target_following_predicate agentClaims)

;; dataContent and propositionalContent are both stated, never derived: no rule here
;; computes either one from an information's author, its encoding or its context. A
;; translation of the same text, or a message with a different author, states its own
;; propositionalContent independently of another information's data content.
(comment dataContent "(dataContent ?info ?string) means that ?string, taken as written, is what ?info holds: the exact sequence of symbols, independent of any byte encoding that stores it. Functional: one piece of information has one data content.")
(binary_predicate dataContent)
(set/monotonic (instance_relation_predicate dataContent))
(arg dataContent 1 information)
(quotedArg dataContent 2 string)
(set/monotonic (functional dataContent))

(comment propositionalContent "(propositionalContent ?info ?proposition) means that ?info says ?proposition. Not functional: one piece of information can say more than one proposition, and two pieces of information with equal data content can say different propositions, e.g. the same words from two different speakers.")
(binary_predicate propositionalContent)
(set/monotonic (instance_relation_predicate propositionalContent))
(arg propositionalContent 1 information)
(arg propositionalContent 2 proposition)

;; ==== perception ==========================================================
;; Arg 1 of every perception relation names the perceiver and declares `thing`: vaelii's
;; `registered_agent` names a registered koinii participant
;; (resources/kb/koinii/CxRegistry.txt), which is a membership mark for an adjudication
;; registry rather than a general type for an entity with agency, and the upper ontology
;; ships no such type.  `seeImage` and `watchVideo`'s second argument is a thing of any
;; kind, so it declares `thing` too.
;;
;; `sees` types its second argument `spatial`, and an image or a video need not be
;; located.  A genl edge from seeImage or watchVideo to sees would carry that declaration
;; down and mint `(spatial Img)` from `(seeImage Ann Img)`, so a rule guarded by the
;; argument type concludes `sees` instead.

;; ---- the perception chain ------------------------------------------------
(comment perceives
         "(perceives ?perceiver ?perceived) means ?perceiver takes in ?perceived through some sense. The most general perception relation; sees specializes it, and seeImage and watchVideo reach it through sees for a spatial second argument.")
(set/monotonic (instance_relation_predicate perceives))
(set/monotonic (time_varying_relation perceives))
(arg perceives 1 thing)
(arg perceives 2 spatial)

(comment sees
         "(sees ?seer ?seen) means ?seer takes in ?seen through sight. Spec of perceives.")
(set/monotonic (instance_relation_predicate sees))
(set/monotonic (time_varying_relation sees))
(arg sees 1 thing)
(arg sees 2 spatial)
(genl sees perceives)

(comment seeImage
         "(seeImage ?seer ?image) means ?seer takes in a static image through sight and perceives what it shows. Its second argument is the image itself, which need not be located, so it concludes sees only of a spatial image (the rule below).")
(set/monotonic (instance_relation_predicate seeImage))
(set/monotonic (time_invariant_relation seeImage))
(arg seeImage 1 thing)
(arg seeImage 2 thing)
(set/forwardRule
  (implies (and (seeImage ?x ?y) (spatial ?y))
           (sees ?x ?y)))

(comment watchVideo
         "(watchVideo ?watcher ?video) means ?watcher takes in a video, a temporal sequence of images, through sight. The video need not be located, so it concludes sees only of a spatial video (the rule below).")
(set/monotonic (instance_relation_predicate watchVideo))
(set/monotonic (time_invariant_relation watchVideo))
(arg watchVideo 1 thing)
(arg watchVideo 2 thing)
(set/forwardRule
  (implies (and (watchVideo ?x ?y) (spatial ?y))
           (sees ?x ?y)))

;; ---- image_viewing: the ability, read as an event kind -------------------
;; life.txt's hasCapability takes a happening kind as its second argument
;; (resources/kb/upper/life.txt): (hasCapability ?x ?happeningKind) means ?x can be the
;; doer of a happening of that kind, and image_viewing is an event kind. image_viewing pairs with seeImage the way flying
;; pairs with flies: the relation states who is looking, the event kind states the
;; ability to be its doer. Taking in an image changes nothing about what it depicts,
;; so image_viewing is a kind of acausal_event, abstract.txt's intersection of acausal
;; and event, whose own comment names an observation as an example.
(comment image_viewing
         "An event of taking in a static image through sight and perceiving what it shows. The event-kind counterpart of seeImage: (hasCapability ?x image_viewing) means ?x can be the doer of one.")
(genl image_viewing acausal_event)
